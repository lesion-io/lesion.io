Lesion.io API

Utilize the API to feed your tooling and workflows, from recon scripts and scanners to reporting pipelines, with a single authenticated JSON request.

The API is a single JSON-over-HTTPS endpoint. Send a POST with a JSON body and you get CVE records back, newest first. The same search powers Lesion Search, so anything you can find in the app you can find here.

Every request needs an API key. See Authentication.

Base URL
https://api.lesion.io
Your first request
curl https://api.lesion.io/search \
  -H "X-API-Key: $LESION_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "apache struts"}'

Authentication

Pass your API key in the X-API-Key header on every request. You can create and revoke keys from your account at app.lesion.io.

Requests without a valid key are rejected with 401 before any search runs.

Treat your key like a password. Call the API from a server, script, or CLI, not from code that runs in someone else's browser.
Header
X-API-Key: lsn_your_key_here

Errors and limits

The API uses standard HTTP status codes. Error bodies are JSON with a detail field.

200Success.
401Missing or invalid API key.
404The CVE ID you looked up isn't in the index. Only returned by CVE ID lookups; searches with no matches return 200 with an empty results list.
422The request body failed validation. detail lists each problem with its location and a message.
429You've hit your rate limit or used your monthly search allowance. Limits depend on your plan; see pricing.
502 / 503The search backend had a problem or is briefly unavailable. Safe to retry with backoff.
422 response
{
  "detail": [
    {
      "loc": ["body", "cve_id"],
      "msg": "Value error, Invalid CVE ID format. Expected: CVE-YYYY-NNNNN",
      "type": "value_error"
    }
  ]
}

Search CVEs

post /search

One endpoint covers three kinds of search, picked by which fields you send:

  • Keyword search: send query.
  • Version-aware search: send query and version.
  • CVE ID lookup: send cve_id.

Every field is optional on its own, but each request needs either query or cve_id. Empty strings, null, and empty lists are treated as "not set".

Request body

querystring, ≤ 200required unless cve_id is set Keywords, or a vendor and product such as apache struts.Letters, numbers, spaces, dots, hyphens and underscores only.
versionstring, ≤ 50 A specific product version. Switches on version-aware search.Letters, numbers, dots, hyphens and underscores only.
cve_idstring, ≤ 20 Look up one CVE directly, such as CVE-2021-44228. Case-insensitive. When set, every other field is ignored.
severityarray of strings Any of none, low, medium, high, critical. A comma-separated string also works. See Filters.
has_exploit_referenceboolean Set true to keep only CVEs with at least one exploit reference.
has_github_reposboolean Set true to keep only CVEs with linked GitHub repositories, such as PoCs.
published_yeararray of integers, ≤ 20 Keep CVEs published in any of these years.1990 to 2100.
cwe_idsarray of strings Keep CVEs tagged with any of these CWEs, such as CWE-79.
pageinteger, default 1 Page number, starting at 1. See Pagination.
page_size25 | 50 | 100, default 25 Results per page.
curl https://api.lesion.io/search \
  -H "X-API-Key: $LESION_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "apache struts",
    "severity": ["critical", "high"],
    "has_exploit_reference": true,
    "page_size": 50
  }'

Keyword search

Send just query. A CVE matches if either of these is true:

  • Its description or nickname contains every word in your query.
  • It lists an affected product whose vendor and product name match your query.

For product matching, the first word is read as the vendor and the rest as the product, so apache http server matches the CPE product http_server from vendor apache. Product names are matched as written in NVD, which usually means lowercase with underscores.

Only products marked as vulnerable count; CPEs listed as running alongside a vulnerable product don't.

Request
{
  "query": "log4j"
}

Version-aware search

Add version to find CVEs that affect that exact release. Here query must be the vendor followed by the product, such as apache http_server or sudo_project sudo.

A CVE matches when one of its vulnerable products has that exact version, or a version range that includes it. Versions are compared segment by segment, so 2.4.9 correctly sorts below 2.4.49.

Matching follows the version format NVD uses for that product, which isn't always as granular as the version you have. If a full version returns nothing, drop the last segment and search again, for example 8.0.2.1 becomes 8.0.2.
Request
{
  "query": "apache http_server",
  "version": "2.4.49"
}

CVE ID lookup

Send cve_id to fetch a single record. The ID is case-insensitive and must look like CVE-YYYY-NNNN with 4 to 10 trailing digits.

The response has the same shape as a search, with exactly one item in results. If the ID isn't in the index you get 404.

Request
{
  "cve_id": "CVE-2021-44228"
}
404 response
{
  "detail": "CVE-2099-0001 not found"
}

Filters

Filters narrow a keyword or version search and can be combined freely. Within one filter, values are OR'd: ["critical", "high"] means critical or high. Across filters, they're AND'd.

Severity

Severity is based on the highest CVSS score recorded for the CVE, across all CVSS versions.

critical9.0 to 10.0
high7.0 to 8.9
medium4.0 to 6.9
low0.1 to 3.9
none0.0

Exploit and PoC flags

has_exploit_reference and has_github_repos only filter when set to true. Sending false is the same as leaving them out; it doesn't return CVEs without exploits.

Years and CWEs

published_year takes up to 20 years. cwe_ids takes CWE IDs in the form CWE-<number>; duplicates are ignored.

Request
{
  "query": "wordpress",
  "severity": ["critical"],
  "has_github_repos": true,
  "published_year": [2024, 2025],
  "cwe_ids": ["CWE-89", "CWE-434"]
}

Pagination and sorting

Results are sorted by publish date, newest first, then by CVSS score, highest first.

Use page and page_size to walk through results. The response tells you how many pages there are.

You can page through the first 10,000 results of any search. Asking for a page past that returns 422. Add filters to narrow the search instead of paging deeper.

For large result sets, total stops counting at 10,000, so treat 10,000 as "10,000 or more".

Deepest page per page size
page_size  last page
       25        400
       50        200
      100        100

totalintegerMatching CVEs, capped at 10,000.
pageintegerThe page you asked for.
page_sizeintegerResults per page.

CVE record

cve_idstringThe CVE identifier.
publisheddatetimeWhen NVD published the CVE.
descriptionstextThe CVE description.
nicknamestringCommon name, such as Log4Shell, when one exists.
